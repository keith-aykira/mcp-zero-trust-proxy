Create `tests/integration/mcp_mock_server.go`:

A configurable mock MCP server that simulates 5 different server behaviors:

1. **Tools-only server** — responds to initialize and tools/list (returns 5 tools), tools/call returns results. Simulates a typical tool-serving MCP server (e.g., filesystem, database).
2. **Resources server** — responds to initialize, resources/list, resources/read. Returns file-like resources. Simulates a resource-serving MCP server (e.g., file browser).
3. **Prompts server** — responds to initialize, prompts/list, prompts/get. Returns prompt templates. Simulates a prompt-serving MCP server.
4. **Mixed server** — responds to all MCP methods (tools + resources + prompts). Simulates a full-featured MCP server.
5. **SSE streaming server** — responds with Server-Sent Events for long-running tool calls. Sends progress events followed by a result event. Simulates servers with streaming responses.

Mock server uses httptest.NewServer. Each server type is configured via a ServerType enum. The mock understands JSON-RPC 2.0 format and returns properly formatted responses.

Create `tests/integration/proxy_test.go`:

Test categories (use Go subtests `t.Run`):

**Server type tests (5):**
- TestProxy_ToolsOnlyServer — proxy forwards tools/list and tools/call correctly
- TestProxy_ResourcesServer — proxy forwards resources/read correctly
- TestProxy_PromptsServer — proxy forwards prompts/get correctly
- TestProxy_MixedServer — proxy handles all method types in one session
- TestProxy_SSEStreamingServer — proxy streams SSE events without buffering (verify events arrive incrementally, not all at once)

**Auth tests:**
- TestProxy_NoAuthHeader_Returns401 — unauthenticated request is rejected
- TestProxy_InvalidToken_Returns401 — bad token is rejected
- TestProxy_ValidToken_Proxies — valid token passes through (use mock token validator that accepts a known test token)

**RBAC tests:**
- TestProxy_AdminRole_FullAccess — admin can call any tool
- TestProxy_ReadOnlyRole_DeniesToolsCall — readonly gets 403 on tools/call
- TestProxy_RestrictedRole_AllowedTool — restricted can call allowed tool
- TestProxy_RestrictedRole_DeniedTool — restricted gets 403 on disallowed tool
- TestProxy_ToolsListFiltered — restricted role's tools/list response only shows allowed tools

**Rate limit tests:**
- TestProxy_UnderRateLimit_Passes — normal rate passes
- TestProxy_OverRateLimit_Returns429 — burst exceeding rate returns error

**Audit tests:**
- TestProxy_AuditLogWritten — every request (allowed and denied) produces audit log entry
- TestProxy_AuditLogFormat — log entries are valid JSON with required fields

**Pipeline tests:**
- TestProxy_HealthCheck — GET /health returns 200
- TestProxy_GracefulShutdown — server accepts new connections during shutdown grace period

For auth tests: since we can't do real OAuth in tests, create a `testAuthenticator` that implements the Authenticator interface and accepts a hardcoded test token. This tests the pipeline integration without requiring real OAuth endpoints.

Create test config YAML files in testdata/ for different test scenarios:
- config_minimal.yaml — just upstream_url and listen_addr (no auth, no RBAC)
- config_github.yaml — GitHub OAuth config (used with mock)
- config_restricted.yaml — restricted role with specific allowed_tools

Use `t.Parallel()` where possible. Use `t.Cleanup()` for teardown.

Create `docs/QUICKSTART.md`:

Structure:
1. **What is MCP Zero-Trust Proxy** — one paragraph explaining the product (reverse proxy, zero code changes, OAuth + RBAC + audit)
2. **Prerequisites** — Docker OR Go 1.22+, an MCP server to protect, an OAuth provider (GitHub or Google account)
3. **Option A: Docker (recommended)** — step by step:
   - `docker pull mcpzerotrust/proxy:latest` (or build from source: `docker build -t mcpzerotrust/proxy .`)
   - Create config.yaml (show minimal example with upstream_url and auth provider)
   - `docker run -p 8080:8080 -v ./config.yaml:/etc/mcpproxy/config.yaml -e OAUTH_CLIENT_SECRET=your_secret mcpzerotrust/proxy:latest`
   - Verify: `curl http://localhost:8080/health`
4. **Option B: Binary** — step by step:
   - `go install github.com/keith-aykira/mcp-zero-trust-proxy/cmd/mcpproxy@latest` or download from releases
   - `mcpproxy --config ./config.yaml`
   - Verify: same curl
5. **Configure your MCP client** — how to point Claude Desktop / Cursor / Copilot at the proxy instead of directly at the MCP server. Show the config change (e.g., for Claude Desktop's claude_desktop_config.json, change the server URL from the MCP server to the proxy).
6. **Set up OAuth provider** — step by step for GitHub (create OAuth App, get client ID/secret, set callback URL to http://localhost:8080/auth/callback) and Google (create OAuth consent screen, create credentials).
7. **Configure RBAC** — show how to define roles in YAML with tool-level permissions. Show the 3 built-in roles and how to assign a role to a client.
8. **Verify it works** — test the full flow: attempt unauthenticated call (should get 401), authenticate via OAuth, make authenticated tools/call (should succeed for admin), check audit log output.
9. **Next steps** — link to config reference, mention rate limiting and audit log configuration.

- Document audit log output format (JSONL schema with field descriptions)

Write for a developer audience. Be direct, show examples, avoid filler. Someone should be able to go from zero to protected MCP server by reading the quick-start guide alone.
