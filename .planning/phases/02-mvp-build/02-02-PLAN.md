Create `internal/proxy/handler.go`:

- `type Handler struct` — holds upstream URL, http.Client, middleware chain (slice of Middleware interfaces from 02-01), Authenticator, AuditLogger, RateLimiter. All middleware fields optional (nil = skip).
- `func NewHandler(cfg *config.Config) (*Handler, error)` — constructs handler from config, parses upstream URL, creates http.Client with reasonable timeouts (30s connect, 120s for SSE).
- `func (h *Handler) ServeHTTP(w http.ResponseWriter, r *http.Request)` — main entry point:
  1. Read and buffer request body (use io.TeeReader pattern so body is available for both parsing and forwarding)
  2. Attempt JSON-RPC parse (if fails, treat as transparent proxy — not all MCP endpoints use JSON-RPC)
  3. Store parsed MCPRequest in context via `context.WithValue`
  4. Run middleware chain: authenticate -> rate limit -> RBAC -> audit (each returns error to deny)
  5. Forward request to upstream
  6. Copy response back to client
  7. For SSE: delegate to ProxySSE

- Key context key: `type contextKey string` with `const MCPRequestKey contextKey = "mcp_request"` and `const ClientIdentityKey contextKey = "client_identity"`

Create `internal/proxy/sse.go`:

- `func ProxySSE(w http.ResponseWriter, r *http.Request, upstream *url.URL) error` — establishes SSE connection to upstream, streams events to client. Uses http.Flusher interface. Handles connection close from either side. Sets proper headers (Content-Type: text/event-stream, Cache-Control: no-cache, Connection: keep-alive).
- Reads upstream SSE line by line using bufio.Scanner, writes to client with immediate flush.
- Respects request context cancellation for cleanup.

Use `net/http/httputil.ReverseProxy` for standard HTTP forwarding. Custom implementation only for SSE (ReverseProxy buffers responses which breaks streaming).

Write tests using httptest.NewServer for both upstream mock and client requests. For SSE tests, use a goroutine to read events.
