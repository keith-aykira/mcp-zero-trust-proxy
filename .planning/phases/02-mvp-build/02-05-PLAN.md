    - Test: Pipeline executes middleware in order: auth -> rate limit -> RBAC (verified by side effects)
    - Test: Auth failure short-circuits pipeline (RBAC and rate limit never called)
    - Test: Rate limit failure short-circuits pipeline (RBAC never called)
    - Test: RBAC denial prevents request from reaching upstream
    - Test: Successful pipeline records audit entry with allowed=true
    - Test: Failed pipeline records audit entry with allowed=false and denied_reason
    - Test: Audit logging happens for BOTH allowed and denied requests
    - Test: Pipeline handles tools/list response filtering via RBAC engine
  </behavior>
  <action>
Create `internal/proxy/pipeline.go`:

- `type Pipeline struct` — holds Handler (from Plan 02), Authenticator, RBAC Engine, RateLimiter, AuditLogger. All optional (nil = skip that step).
- `func NewPipeline(handler *Handler, auth *auth.Authenticator, rbac *rbac.Engine, rl *ratelimit.Limiter, audit *audit.Logger) *Pipeline`
- `func (p *Pipeline) ServeHTTP(w http.ResponseWriter, r *http.Request)` — the main HTTP handler:
  1. Generate request ID (UUID or short random string)
  2. Start timer for latency tracking
  3. **Authenticate**: if auth != nil, call auth.Authenticate(r). On failure, write JSON-RPC Unauthorized error, log audit (denied), return.
  4. **Rate limit**: if rl != nil, call rl.Allow(identity.ClientID). On failure, write JSON-RPC RateLimited error, log audit (denied), return.
  5. **Parse request**: read body, call ParseRequest. Store in context.
  6. **RBAC**: if rbac != nil, call rbac.Process(ctx, req, identity). On failure, write JSON-RPC Forbidden error, log audit (denied), return.
  7. **Proxy**: forward to upstream via handler.
  8. **Post-proxy**: for tools/list responses, intercept and filter through rbac.FilterToolsList.
  9. **Audit**: log audit entry (allowed=true, latency computed).

- Handle OAuth flow routes separately: GET /auth/start -> auth.HandleAuthStart, GET /auth/callback -> auth.HandleCallback. These bypass the middleware pipeline.
- Health check: GET /health returns 200 {"status":"ok"} (bypass all middleware).

For tools/list response filtering (step 8): use a custom ResponseWriter that captures the response body, parses the tools/list result, filters it, and writes the filtered version to the real ResponseWriter.

Write tests FIRST using mock implementations of each interface (simple structs that track calls), then implement.

RUN go mod download
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -ldflags="-s -w -X main.version=${VERSION:-dev}" -o /mcpproxy ./cmd/mcpproxy

FROM alpine:3.19

COPY --from=builder /mcpproxy /usr/local/bin/mcpproxy

ENTRYPOINT ["mcpproxy"]
