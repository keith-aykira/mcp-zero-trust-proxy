    - Test: Batch with all items denied — returns batch of JSON-RPC errors
    - Test: Single (non-batch) request behavior unchanged
    - Test: Batch audit log records each item separately with its own allowed/denied status
    - Test: Empty batch returns empty array response
  </behavior>
  <action>
    1. **Detect batch requests:**
       - In `runPipeline`, after parsing the body with `ParseRequest(bodyBytes)`, check `len(reqs) > 1` to detect batch mode.
       - Store the full `reqs []*MCPRequest` slice, not just `reqs[0]`.

    2. **Per-item RBAC for batch:**
       - Add a `processBatch` method to Pipeline:
         ```go
         func (p *Pipeline) processBatch(w http.ResponseWriter, r *http.Request, reqs []*MCPRequest, identity *ClientIdentity, bodyBytes []byte, start time.Time, requestID string)
         ```
       - For each item in the batch:
         a. Run RBAC check via `p.rbac.Process(ctx, req, identity)`
         b. If denied: build a JSON-RPC error response for that item's ID with 403 code
         c. If allowed: include the original request in the forwarded batch
         d. Log an audit entry for each item (method, tool_name, allowed/denied)
       - After processing all items:
         - If ALL denied: write the batch of error responses directly (don't forward)
         - If SOME allowed: forward only allowed items as a batch to upstream, then merge upstream responses with the pre-built error responses for denied items
         - Simplification: forward the entire original batch to upstream (upstream handles all), then post-process: replace responses for denied items with RBAC error responses. This avoids reconstructing partial batches.
       - Actually, the cleanest approach: iterate each request, check RBAC. Build a response array. For allowed items, forward individually to upstream (or as a batch). For denied items, add error responses. This avoids the complexity of partial batch forwarding.

    3. **Practical implementation (simple and correct):**
       - In `runPipeline`, when batch detected:
         - Create a `[]json.RawMessage` for batch responses
         - For each req in reqs:
           - Check RBAC -> if denied, append JSON-RPC error response
           - If allowed, forward to upstream individually (using responseCapture), append result
           - Log audit entry per item
         - Write the full batch response array as JSON
       - This is simple and correct. Performance optimization (batch forwarding) can come later if needed.

    4. **Wire into runPipeline:**
       - After `ParseRequest` returns multiple requests, branch: `if len(reqs) > 1 { p.processBatch(...); return }`
       - Single request path remains unchanged (existing code)
